# P0 掌握度画像与加权出题 · 产品方案

> 版本:v0.1
> 作者:从传领
> 日期:2026-11-16
> 关联:[面试复习闭环-PRD](面试复习闭环-PRD.md) 的 F-06 / F-07、[AI面试-技术设计](AI面试-技术设计.md)
> 一句话:把每场面试的逐题评分沉淀为"用户 × 知识点"的掌握度画像,下一场按薄弱程度和遗忘程度加权选题,让系统越用越准。

---

## 1. 现状与问题

AI 面试已经跑通"出题 → 追问 → 评分 → 复盘"的单场闭环,但跨场没有记忆:

1. 逐题评分里的 `knowledgePoints` 只落在 `interview_questions` 一行上,没有按用户汇总。
2. 复盘报告的 `weakPoints` 是"这一场的总结",展示完即弃,不参与下一场出题。
3. 下一场出题只读取"本场已考察知识点"做去重,用户上一场暴露的弱点完全丢失。

结果:产品更像"随机模拟面试",而不是 PRD 定位的"针对个人弱点的复习系统",也无法证明"越练越准"这个核心价值。

---

## 2. 目标与非目标

### 2.1 产品目标

- 用户完成第一场面试后,从第二场开始能明显感到"它在追着我的弱点问"。
- 弱点可见、可解释:用户能看到每个知识点的掌握度、最近一次得分和趋势。
- 默认生效,不增加配置负担:不需要用户手动选题或设置复习计划。

### 2.2 成功指标

| 指标 | 定义 | 目标值 |
|---|---|---|
| 薄弱点覆盖率 | 第二场及以后,历史薄弱知识点被实际考察的场次占比 | ≥ 60% |
| 掌握度提升 | 连续 3 场内,用户平均掌握度的提升幅度 | ≥ 10 分 |
| 画像页访问率 | 完成面试的用户中,打开过画像页的比例 | ≥ 40% |
| 次日/7 日复用率 | 北极星指标,验证闭环是否真的有用 | 持续观察 |

### 2.3 非目标(本 P0 明确不做)

- ❌ SM-2 / 遗忘曲线排期、每日复习计划。
- ❌ 题库、错题本、按知识点生成相似题。
- ❌ 雷达图、热力图等复杂可视化(本 P0 只做列表 + 进度条)。
- ❌ 参考答案生成:面试过程中展示答案会破坏追问的真实性,归入后续"错题/复盘"模块。
- ❌ 跨题对话上下文复用。
- ❌ 多实例分布式锁、画像实时推送。

## 3. 用户旅程

### 3.1 现状

```
上传简历 → 创建面试 → 出题(只看本场) → 回答 → 评分 → 复盘报告(看完即弃)
                              ↑                                      │
                              └──────────── 下一场从零开始 ───────────┘
```

### 3.2 目标

```
上传简历 → 创建面试 → 读取历史画像 → 按薄弱点加权选题 → 出题
                ↑                                            │
                │                                            ↓
        更新掌握度画像 ←── 逐题评分(知识点 + 1~5 分) ←── 回答/追问
                │
                └── 画像页 / 面试入口薄弱点卡片 / 复盘提示
```

关键变化:**每场面试结束时,系统已经比上一场更了解用户**。

## 4. 功能范围

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| P0-1 | 知识点归一与画像沉淀 | 把每题的知识点 + 评分汇总为"用户 × 知识点"记录 | P0 |
| P0-2 | 加权出题 | 出题前按薄弱度、错题、遗忘时间选候选知识点,写入 prompt | P0 |
| P0-3 | 面试入口薄弱点卡片 | 展示 Top 5 薄弱知识点,让用户感知系统记得他 | P0 |
| P0-4 | 掌握度画像页 | 列表展示全部知识点的掌握度、练习次数、最近得分、趋势 | P0 |
| P0-5 | 复盘报告联动 | 报告弹窗增加"已同步到画像"提示和入口 | P0 |
| P0-6 | 画像重建 | 管理员按用户从历史面试记录重算画像,用于修复/回填 | P0 |

排序原则:**先把"沉淀"和"用起来"做通(P0-1 / P0-2),再补可见性(P0-3 / P0-4 / P0-5)**。没有 P0-1/2,画像页只是好看的空壳。

## 5. 核心规则

### 5.1 知识点从哪里来

- 沿用现有评分输出:每题收束时 LLM 返回 1~3 个 `knowledgePoints` 和 1~5 分。
- 后端做**名称归一**:去首尾空格、统一大小写、去中文/英文标点与空白。归一后相同的名称视为同一知识点。
- 评分 prompt 中附带用户已有的知识点名称,要求模型**优先复用完全一致的名称**,减少"Redis 持久化 / Redis持久化机制"这类碎片。
- 知识点按关键词推断领域(Redis / MySQL / JVM / Java / 网络 / 操作系统 / 算法 / AI / 项目 / 其他),用于画像页筛选。

### 5.2 掌握度怎么算

单次得分映射为观测值:

| 本题得分 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 观测值 | 0 | 25 | 50 | 75 | 100 |

掌握度使用指数移动平均(EMA),兼顾稳定性和及时性:

```
首次考察:  掌握度 = 观测值
再次考察:  新掌握度 = round(旧掌握度 × 0.7 + 观测值 × 0.3)
```

示例:某知识点原掌握度 80,本次答 1 分 → 新掌握度 = 80×0.7 + 0×0.3 = 56,一次明显下滑;下次答 5 分 → 56×0.7 + 100×0.3 = 69,逐步回升。

等级与趋势:

| 掌握度 | 等级 | 展示 |
|---|---|---|
| 0 ~ 39 | 薄弱 | 红色,优先出题 |
| 40 ~ 74 | 待巩固 | 黄色 |
| 75 ~ 100 | 已掌握 | 绿色 |

- 趋势 = 本次掌握度与上一次掌握度比较,分为上升 / 下降 / 持平;首次考察显示"新"。
- 正确次数口径:本题得分 ≥ 3 记为一次正确。

### 5.3 加权出题怎么加权

每个已考察过的知识点计算权重:

```
权重 = 等级权重 + 错题加成 + 遗忘加成

等级权重:  掌握度 < 40 → 3.0
           40 ~ 74     → 1.8
           ≥ 75        → 1.0
错题加成:  最近一次得分 ≤ 2 → +1.5
遗忘加成:  min(距上次练习天数, 30) / 30 × 1.0
```

按权重随机抽取 **5 个**候选知识点,排除本场已考察过的,写入出题 prompt:

```
参考薄弱知识点(按优先级,若与岗位/简历不相关可忽略):
1. Redis 持久化(掌握度 35,薄弱,最近一次 2 分)
2. ...
```

LLM 有最终决定权:优先从候选中选题;如果候选都不适合当前简历/岗位,可以自行出题,但不得重复本场已考察知识点。这样既保证"追弱点",又不会出现"简历里没有 Redis 却硬问 Redis"。

示例:

| 知识点 | 掌握度 | 最近得分 | 距上次 | 权重 | 被抽中概率 |
|---|---|---|---|---|---|
| Redis 持久化 | 35 | 2 | 10 天 | 3.0 + 1.5 + 0.33 = 4.83 | ≈ 58% |
| MySQL 索引 | 70 | 4 | 2 天 | 1.8 + 0 + 0.07 = 1.87 | ≈ 22% |
| JVM GC | 85 | 5 | 20 天 | 1.0 + 0 + 0.67 = 1.67 | ≈ 20% |

### 5.4 冷启动

- 画像为空:出题完全沿用现有逻辑,不做任何加权,用户无感知。
- 新岗位:历史画像仍然参与候选,但 prompt 明确允许模型忽略与岗位/简历不相关的知识点。
- 新用户第一场:不会因为"没有画像"而降低出题质量。

### 5.5 报告与画像的关系

- **画像只由逐题评分驱动**,不用报告里的 `weakPoints` 二次写入,避免同一场重复计数。
- 报告是"这一场发生了什么",画像是"长期事实",两者职责分开。
- 报告弹窗只增加一句提示和画像入口,不改动报告内容。

## 6. 页面与交互

### 6.1 AI 面试入口(`/interview`)

在面试配置区上方增加一张"你的薄弱知识点"卡片:

```
你的薄弱知识点                        查看完整画像 →
[Redis 持久化 35] [MySQL 索引 42] [JVM GC 48] [网络 TCP 51] [分布式锁 55]
完成面试后,系统会自动把评分沉淀到画像,下一场优先考察薄弱点。
```

- 最多展示 5 个,按掌握度从低到高。
- 画像为空时整张卡片隐藏,不出现空状态。
- 卡片只做展示和跳转,不增加"选择知识点"的配置项,保持创建流程简单。

### 6.2 面试过程

- 不新增任何操作。
- 出题 prompt 已带薄弱点候选,用户只会感到"问得更准",不会被额外打扰。

### 6.3 复盘报告弹窗

报告底部增加:

```
本场评分已同步到你的掌握度画像。 去看看薄弱点 →
```

### 6.4 掌握度画像页(`/knowledge`,新增侧边栏入口)

**顶部统计**:平均掌握度、薄弱数、待巩固数、已掌握数。

**筛选**:等级(全部 / 薄弱 / 待巩固 / 已掌握)+ 领域下拉。

**列表字段**:

| 字段 | 说明 |
|---|---|
| 知识点名称 | 主标题 |
| 领域标签 | Redis / MySQL / JVM 等 |
| 掌握度 | 进度条 + 数字 |
| 等级 | 薄弱 / 待巩固 / 已掌握 |
| 趋势 | ↑ / ↓ / → |
| 练习次数 | 累计被考察次数 |
| 最近得分 | 最近一次 1~5 分 |
| 最近练习时间 | 相对时间,如"3 天前" |

**排序**:默认掌握度从低到高;同分时最近练习时间早的在前。

**空状态**:

```
还没有掌握度画像
完成一场 AI 面试后,这里会按知识点汇总你的表现。
[开始一场面试]
```

**移动端**:统计卡两列,列表项纵向排列,不做横向表格。

### 6.5 文案口径

- 对用户统一说"掌握度",不说"画像分"或"能力值"。
- 薄弱点描述使用"最近一次答得不够好",避免"你很差"这类负面表达。

## 7. 边界与异常

| 场景 | 行为 |
|---|---|
| 画像为空 | 入口卡片隐藏;出题沿用旧逻辑;画像页展示空状态 |
| 同一知识点名称有细微差异 | 归一化后合并;仍无法合并的留到后续人工合并 |
| 一场面试重复提交同一题 | 题目只能收束一次,画像不会重复累加 |
| 画像更新失败 | 不影响答题成功;记录日志,可通过"画像重建"修复 |
| 删除面试记录 | 画像不回滚,视为长期统计;需要时可重建 |
| 知识点与岗位无关 | LLM 可忽略候选;不会硬凑 |
| LLM 一次返回多个知识点 | 每个知识点都按本题得分更新一次 |
| 历史数据 | 上线后对已有用户执行一次画像重建,补齐历史场次 |

## 8. 验收标准

| # | Given | When | Then |
|---|---|---|---|
| 1 | 用户完成一场 3 题面试 | 查看画像页 | 出现本场评分的知识点,掌握度/练习次数/最近得分与逐题评分一致 |
| 2 | 某知识点已有画像 | 再次被评分 | 练习次数 +1,掌握度按 EMA 更新,趋势正确 |
| 3 | 用户存在薄弱知识点 | 创建第二场面试并出题 | 出题 prompt 包含该薄弱点;若模型采用,题目围绕它展开 |
| 4 | 薄弱点在本场已被考察 | 继续出下一题 | 该知识点不再出现在候选里 |
| 5 | 用户没有任何画像 | 创建面试 | 出题行为与本版本一致,不报错 |
| 6 | 画像更新过程中数据库异常 | 提交回答 | 回答仍然保存成功,日志有记录,后续可重建 |
| 7 | 管理员触发画像重建 | 重建完成 | 画像与现存已收束题目重算结果一致 |
| 8 | 删除一场面试 | 查看画像 | 画像不自动回滚;重建后才反映删除结果 |

## 9. 里程碑

| 阶段 | 内容 | 产出 |
|---|---|---|
| M1 | 数据表 + 知识点归一 + 掌握度计算 + 答题后沉淀 | 后端可产出画像数据 |
| M2 | 加权候选 + 出题 prompt 改造 + 画像查询接口 | 第二场开始"追弱点" |
| M3 | 画像页 + 面试入口卡片 + 报告提示 | 用户可见、可验证 |
| M4 | 画像重建 + 历史数据回填 + 验收 | 可上线 |

M1/M2 是闭环内核,必须先于 M3;否则画像页没有真实数据可展示。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 知识点命名碎片化,画像被拆散 | 评分 prompt 强制复用已有名称 + 后端归一化;后续再做人工合并 |
| 加权过猛,总问同样几道弱点 | 权重随机抽样 + 排除本场已考察 + 遗忘加成;避免连续多场只考一个点 |
| 冷启动没有画像,用户感知不到 | 入口卡片隐藏;第一场仍按简历正常出题,第二场开始体现差异 |
| 画像更新失败导致数据缺失 | 答题主流程优先,画像最终一致;提供重建能力 |
| 用户误以为系统"只会问弱点" | 文案说明"优先考察薄弱点,同时覆盖简历其他方向" |
| 指标好看但用户不用 | 以次日/7 日复用率为北极星,不以画像数量自嗨 |

## 11. 已拍板与待确认

已拍板:

1. 默认开启加权,不提供用户开关。
2. 画像跨岗位共享,由 LLM 判断相关性。
3. 报告不写入画像,避免重复计数。
4. 本 P0 不做 SM-2、题库、错题本、雷达图、参考答案。

待确认(建议默认值):

1. EMA 系数采用 0.7 / 0.3(默认),后续可按真实数据调整。
2. 候选知识点数量固定 5 个(默认)。
3. 画像页是否展示"未考察"的知识点(默认不展示)。
4. 是否提供用户自助"重置画像"(默认不提供,后续需要再加)。
