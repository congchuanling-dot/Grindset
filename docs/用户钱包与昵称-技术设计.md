# 用户钱包与昵称 · 技术设计

> 版本：v0.1
> 作者：从传领
> 日期：2026-11-26
> 关联：[AGENTS.md](../AGENTS.md)、[登录模块-技术设计](登录模块-技术设计.md)、[015_ai_usage_schema.sql](../sql/015_ai_usage_schema.sql)、[017_user_wallet_schema.sql](../sql/017_user_wallet_schema.sql)
> 一句话：钱包独立于 `users` 表，注册送 1 元；所有模型调用按实际成本扣费并写流水，余额不足在 `LlmRouter` 统一拦截；侧边栏展示昵称与余额，支持修改昵称。

---

## 1. 背景与目标

### 1.1 背景

改造前项目已经有两块基础，但都没形成完整的用户侧能力：

- [ai_usage_record](../sql/015_ai_usage_schema.sql) 已经记录每次模型调用的 token 与成本，但没有"用户自己的钱"，无法限制消费
- `users.nickname` 已存在，但前端 [authStore](../frontend/src/auth/authStore.ts) 只存了邮箱，侧边栏展示的是账号，也没有修改入口

### 1.2 目标

| 能力 | 说明 |
|---|---|
| 钱包 | 一个用户一个钱包，默认 1 元，独立于认证表 |
| 流水 | 每次余额变动写一条 `user_balance_log`，支持分页查看 |
| 扣费 | 模型调用成功后按 `ai_usage_record.cost` 扣减余额 |
| 余额闸门 | 余额 ≤ 0 时拦截，不调用上游模型 |
| 昵称 | 支持修改，登录/刷新后侧边栏正确展示 |
| 展示 | 侧边栏显示昵称、邮箱、余额；新增"我的钱包"页面 |

### 1.3 非目标

- 在线充值 / 支付 / 退款
- 幂等扣费（重试与补偿可能重复扣，二期补）
- 冻结金额、多币种、账单对账
- 管理端调账页面
- 多实例下的分布式余额一致性（项目仍是单实例假设）

## 2. 数据模型

### 2.1 user_wallets

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 雪花 ID，应用生成 |
| user_id | BIGINT | 关联 `users.id`，唯一索引 |
| balance | DECIMAL(18,8) | 余额，默认 `1.00000000` |
| currency | VARCHAR(8) | 默认 `CNY` |
| created_at | DATETIME | |
| updated_at | DATETIME | 扣费时自动更新 |

设计取舍：

- **独立表而不是给 `users` 加列**：认证与资金解耦，后续加冻结金额、版本号不用动登录表。
- **精度 18,8 与 `ai_usage_record.cost` 对齐**：单次对话可能只有几厘钱，用 4 位小数会被抹成 0。
- **`UNIQUE(user_id)`**：一个用户只能有一个钱包，并发懒创建时由它兜底。

### 2.2 user_balance_log

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 雪花 ID |
| user_id | BIGINT | 关联 `users.id` |
| change_amount | DECIMAL(18,8) | 正数入账、负数消费 |
| balance_before | DECIMAL(18,8) | 变动前余额 |
| balance_after | DECIMAL(18,8) | 变动后余额 |
| change_type | VARCHAR(16) | `INIT` / `RECHARGE` / `CONSUME` / `ADJUST` |
| biz_type | VARCHAR(32) NULL | 取 `AiBizType.name()`，初始化/调账为空 |
| biz_ref | VARCHAR(64) NULL | 会话 / 面试 / 简历 ID |
| remark | VARCHAR(255) NULL | 备注，调账用 |
| created_at | DATETIME | |

索引：

- `idx_user_time(user_id, created_at)`：按用户倒序分页
- `idx_type_time(change_type, created_at)`：按类型统计

本期**不加** `(biz_type, biz_ref)` 唯一索引，留给幂等迭代。

### 2.3 建表脚本

```sql
CREATE TABLE IF NOT EXISTS user_wallets (
    id          BIGINT        NOT NULL COMMENT '主键,雪花 ID',
    user_id     BIGINT        NOT NULL COMMENT '关联 users.id',
    balance     DECIMAL(18,8) NOT NULL DEFAULT 1.00000000 COMMENT '余额,元',
    currency    VARCHAR(8)    NOT NULL DEFAULT 'CNY' COMMENT '币种',
    created_at  DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_user_id (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户钱包';

CREATE TABLE IF NOT EXISTS user_balance_log (
    id             BIGINT        NOT NULL COMMENT '主键,雪花 ID',
    user_id        BIGINT        NOT NULL COMMENT '关联 users.id',
    change_amount  DECIMAL(18,8) NOT NULL COMMENT '变动金额,正=入账 负=消费',
    balance_before DECIMAL(18,8) NOT NULL COMMENT '变动前余额',
    balance_after  DECIMAL(18,8) NOT NULL COMMENT '变动后余额',
    change_type    VARCHAR(16)   NOT NULL COMMENT 'INIT/RECHARGE/CONSUME/ADJUST',
    biz_type       VARCHAR(32)   NULL COMMENT '业务类型,取 AiBizType.name()',
    biz_ref        VARCHAR(64)   NULL COMMENT '会话/面试/简历 ID',
    remark         VARCHAR(255)  NULL COMMENT '备注,调账用',
    created_at     DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_user_time (user_id, created_at),
    KEY idx_type_time (change_type, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户余额流水';
```

脚本可重复执行；存量用户不需要补数，首次访问时懒创建。

### 2.4 存量用户处理

- 注册流程在事务内创建钱包 + `INIT` 流水
- 老用户第一次访问 `/api/wallet` 或第一次调用 AI 时，`ensureWallet` 懒创建钱包（同样 1 元 + `INIT`）
- 并发懒创建由 `uk_user_id` 兜底，捕获 `DuplicateKeyException` 后重查

### 3.2 WalletService

| 方法 | 行为 |
|---|---|
| `ensureWallet(userId)` | 查不到就懒创建（1 元 + INIT 流水），重复键后重查 |
| `initWallet(userId)` | 注册事务内调用，等价于 `ensureWallet` |
| `getInfo(userId)` | 返回余额、币种、更新时间 |
| `logs(userId, page, size)` | 分页查流水，`size` 夹到 1~100 |
| `assertAffordable(userId)` | 余额 ≤ 0 抛 `BizException(402)`；DB 异常 fail-open 放行 |
| `consume(userId, amount, bizType, bizRef)` | 金额 ≤ 0 跳过；原子扣减成功才写 CONSUME 流水 |

项目统一用 `TransactionTemplate`，不使用 `@Transactional` 注解；`consume` 的事务只覆盖"扣余额 + 写流水"。

### 3.3 扣费与拦截时序

1. 用户触发 AI → Controller → Service → `LlmRouter`
2. `LlmRouter` 入口调用 `assertAffordable(userId)`，余额 ≤ 0 直接返回 402，**不调用上游**
3. 调用成功 → `AiUsageService.record` 计算 `cost` 并写 `ai_usage_record`
4. 紧接着 `WalletService.consume` 原子扣减
5. 扣减成功 → 写 `CONSUME` 流水；影响行数为 0 → 记 warn（这笔超支）
6. 查询余额直接读 `user_wallets`，不再聚合 `ai_usage_record`

为什么闸门放在 `LlmRouter`：所有模型调用（首页对话、Agent、会话标题、面试出题/点评/复盘、题库评分、简历解析）都经过它，且 `LlmUsageContext` 都带真实 `userId`，一处拦截覆盖全部调用点。

### 3.5 错误码与 SSE 行为

- 新增 `402 PAYMENT_REQUIRED`，`GlobalExceptionHandler` 通过 `HttpStatus.resolve(402)` 映射为标准 402
- 非流式接口（如题库评分）直接返回 `{"code":402,"message":"余额不足，请充值后继续"}`
- 流式接口（对话 / Agent / 面试出题）由 Controller 捕获 `BizException` 后发送 `event: error`，前端 [chat.ts](../frontend/src/api/chat.ts)、[agent.ts](../frontend/src/api/agent.ts)、[interview.ts](../frontend/src/api/interview.ts) 已有 `onError`，无需改动即可展示

### 3.6 事务、并发与容错

| 关注点 | 做法 |
|---|---|
| 余额不为负 | `UPDATE ... SET balance = balance - ? WHERE user_id = ? AND balance >= ?` |
| 事务边界 | `TransactionTemplate` 只包扣余额 + 写流水，模型调用在事务外 |
| 记账失败 | `AiUsageService.record` 已有 try/catch，扣费异常同样只记日志 |
| 校验期间并发 | 闸门与扣费之间有窗口，最多透支一次调用 |
| DB 故障 | 闸门 fail-open，避免钱包拖垮 AI 主流程 |
| 流水 before/after | 同事务内先读后改，高并发下可能不准（已接受的取舍） |

## 4. 昵称

### 4.1 校验规则

- `strip()` 后按 code point 计 2~20 个字符（中文、emoji 各算一个）
- 不允许控制字符
- 不要求唯一

### 4.2 前端回填

`Session` 增加 `nickname`，三处必须写入，否则刷新后侧边栏会空：

| 入口 | 位置 |
|---|---|
| 登录 / 注册 | [LoginPage.tsx](../frontend/src/pages/LoginPage.tsx) |
| OAuth 回调 | [AuthCallbackPage.tsx](../frontend/src/pages/AuthCallbackPage.tsx) |
| 静默刷新 | [http.ts](../frontend/src/api/http.ts) 的 `ensureRefreshed` |

OAuth 登录后端只返回昵称、没有单独邮箱，`account` 与 `nickname` 相同时侧边栏不重复展示邮箱。

## 6. 边界与已知取舍

| 风险 | 当前处理 | 后续方向 |
|---|---|---|
| 重试/补偿重复扣费 | 不做幂等 | `(biz_type, biz_ref)` 唯一索引或 `usage_record_id` |
| 流水 before/after 并发不准 | 接受 | `version` 乐观锁或行锁 |
| 记账失败导致用了没扣 | 只记 warn | 对账任务补偿 |
| 闸门与扣费之间窗口 | 最多超支一次 | 预扣/冻结额度 |
| DB 故障 | fail-open | 降级开关 |
| 1 元花完无法自助恢复 | 本期无充值 | 用户端充值接口 |
| 管理端调账 | 不做 | 后台调账入口 + ADJUST 流水 |

## 8. 后续迭代

1. **幂等扣费**：给 `user_balance_log` 加 `(biz_type, biz_ref)` 唯一索引，或直接记录 `usage_record_id` 唯一
2. **并发准确性**：`user_wallets` 加 `version`，扣费改用乐观锁，流水 before/after 才准确
3. **充值**：用户端充值接口 + 支付回调，写 `RECHARGE` 流水
4. **管理端调账**：`ADJUST` 流水 + 备注，支持人工补偿
5. **对账**：定时比对 `ai_usage_record.cost` 总和与 `CONSUME` 流水总和
6. **余额缓存**：热点用户余额可放 Redis，但扣费必须落库
