# 错题重练闭环 · 产品方案（PRD）

> 版本：v0.1
> 作者：从传领
> 日期：2026-11-16
> 关联：[面试复习闭环-PRD](面试复习闭环-PRD.md) 的 F-10 / P1 错题、[P0-掌握度画像与加权出题-产品方案](P0-掌握度画像与加权出题-产品方案.md)、[AI面试-技术设计](AI面试-技术设计.md)
> 一句话：把面试里答得不好的题自动收进错题本，用“重练 → 评分 → 参考要点 → 画像回写”把一次失败变成下一次练习的起点。

---

## 1. 现状与问题

P0 已经跑通“单场面试 + 跨场掌握度画像”，但闭环还差最后一环：

1. **错题没有留存**：一道题答完、评分完就结束了，用户之后再也找不到“当时那道题、我当时怎么答的”。
2. **复盘报告太粗**：报告里的 `weakPoints` 是“这一场哪里弱”，不能逐题重练，也不能回答“这道题的正确思路是什么”。
3. **评分只有分数**：现有评分给 1~5 分和一句建议，没有参考要点，用户知道自己差，但不知道差在哪、怎么补。
4. **画像只有“知道”，没有“做到”**：画像告诉用户“HashMap 薄弱”，但用户没有一个具体的练习动作去改变它。

结果：产品能诊断，却不能治疗。用户看完画像和报告，下一步仍然是自己去找题、找答案。

## 2. 目标与非目标

### 2.1 产品目标

- **自动**：答得不好的题自动进错题本，不需要用户手动收藏。
- **可重练**：每道错题都能单独重答，提交后立即得到评分和参考要点。
- **可闭环**：重练结果回写掌握度画像，下一场面试继续追这个弱点。
- **可解释**：原题、原回答、原评分、参考要点都能看到，用户知道差距在哪。

### 2.2 成功指标

| 指标 | 定义 | 目标值 |
|---|---|---|
| 错题重练率 | 收录的错题中，7 天内至少重练 1 次的比例 | ≥ 30% |
| 重练掌握率 | 重练过的错题中，最近一次得分 ≥ 3 的比例 | ≥ 50% |
| 错题本访问率 | 有错题的用户中，打开过错题本的比例 | ≥ 30% |
| 画像提升 | 重练过的知识点，掌握度平均提升 | ≥ 10 分 |
| 7 日复用率 | 北星指标，验证“重练”是否真的带来回访 | 持续观察 |

### 2.3 非目标（本期明确不做）

- ❌ 手动录入错题、贴题生成相似题（PRD 中的 F-10，归 P1）。
- ❌ SM-2 / 遗忘曲线排期、每日复习计划、站内信/邮件/微信提醒。
- ❌ 题库、按知识点批量出题、相似题生成。
- ❌ AI 陪练对话、多轮讲解、语音作答。
- ❌ 标准答案库、完整参考答案全文。
- ❌ 错题删除、归档、导出。
- ❌ 多实例分布式锁、错题实时推送。

## 3. 用户旅程

### 3.1 现状

```
面试答题 → 本题评分 → 复盘报告（看完即弃） → 下一场从零开始
                              │
                              └── 错题没有留下，弱点只停留在画像数字上
```

### 3.2 目标

```
面试答题 → 本题收束，score ≤ 2
              │
              ▼
      自动收录错题快照（题目 / 原回答 / 原评分 / 知识点）
              │
              ▼
      错题本（待重练） → 单题重练 → AI 评分 + 参考要点
              │                              │
              │                              ▼
              └──── 标记已掌握 / 继续待重练 ←── 回写掌握度画像
                              │
                              ▼
                    下一场面试按薄弱点加权出题
```

关键变化：**每一道错题都成为下一次练习的入口**，画像不再只是“诊断报告”，而是“练习清单”。

## 4. 功能范围

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| P0-1 | 错题自动收录 | 本题收束且得分 ≤ 2 时，自动保存题目、原回答、原评分、知识点快照 | P0 |
| P0-2 | 错题本列表 | 按待重练 / 已掌握 / 全部查看，支持知识点和本场面试筛选 | P0 |
| P0-3 | 单题重练 | 在错题本内单独重答一道题，提交后立即评分 | P0 |
| P0-4 | 参考要点 | 重练提交后由 AI 生成 3~6 条参考要点，提交前不展示 | P0 |
| P0-5 | 画像回写 | 重练分数按现有 EMA 规则回写知识点掌握度 | P0 |
| P0-6 | 入口联动 | 答题后提示、复盘报告、掌握度画像、面试入口都能进入错题本 | P0 |
| P0-7 | 历史回填 | 管理员按用户扫描历史已收束题目，补齐错题快照 | P0 |
| P0-8 | 重练历史与状态流转 | 每次重练留记录；≥3 分已掌握，<3 分回退待重练 | P0 |

排序原则：**先“收得进来”（P0-1），再“练得起来”（P0-3/4/5），最后补入口和可见性（P0-2/6）**。没有 P0-1，错题本是空的；没有 P0-3/5，错题本只是一个只读列表。

## 5. 核心规则

### 5.1 哪些题算错题

- 本题**收束时**得分 `score ≤ 2`，自动收录。
- 一道题只收录一次，以 `(user_id, question_id)` 唯一约束兜底，重复收束不会重复收录。
- 未收束、没有评分的题不收录。
- 得分 3 分表示“基础过关”，不自动收录；后续 P1 可提供“手动加入错题本”。
- 复盘报告里的 `weakPoints` 不参与收录，避免同一道题被重复计算。

### 5.2 错题快照包含什么

| 字段 | 说明 |
|---|---|
| 题目 | 本题主问题原文 |
| 追问上下文 | 本题所有追问问题，按顺序拼接 |
| 原回答 | 本题所有作答，按顺序拼接 |
| 原评分 | 本题 1~5 分 |
| 原点评 | 本题总评 |
| 原建议 | 本题改进建议 |
| 原逐轮点评 | 作答过程中每次一句话点评，拼接保存 |
| 知识点 | 本题命中的 1~3 个知识点名称及 ID |
| 岗位 / 轮次 | 当时的面试岗位和轮次，供重练评分参考 |
| 来源会话 | 原面试会话 ID，便于回溯 |

快照独立于原面试：删除面试记录、删除简历，都不会让错题消失。

### 5.3 状态流转

```
待重练 PENDING ──重练 score ≥ 3──▶ 已掌握 MASTERED
      ▲                                  │
      └──────── 重练 score < 3 ──────────┘
```

- 重练得分 ≥ 3：标记“已掌握”，记录 `mastered_at`。
- 重练得分 < 3：保持/回退“待重练”，清空 `mastered_at`。
- 已掌握的错题仍允许“再练一次”；如果再次低于 3 分，状态回退，不保留“曾经掌握”的假象。
- 每次重练都写一条历史记录，不覆盖上一次。

### 5.4 复习时间

| 最近一次重练得分 | 下次建议复习 |
|---|---|
| < 3 | 1 天后 |
| = 3 | 3 天后 |
| ≥ 4 | 7 天后 |

- 新收录的错题：`next_review_at = 收录时间`，即“现在就可以练”。
- “今日待复习”= 待重练 且 `next_review_at ≤ 当前时间`。
- 本期不做提醒推送，只在错题本顶部展示统计。

### 5.5 参考要点

- 提交重练后由 AI 生成，定位是“参考要点”，不是标准答案。
- 3~6 条，每条以 `- ` 开头，每条不超过 60 字。
- 提交前不展示参考要点，原回答也先隐藏，避免用户直接照抄。
- 每次重练都生成一份，保留在重练历史里。
- UI 明确标注“参考要点由 AI 生成，仅供复习参考”。

### 5.6 画像回写

- 重练使用**错题快照里的知识点**，不允许模型在重练时新增或改写知识点。
- 重练分数按现有 P0 的 EMA 规则回写掌握度：
  - 1 分 → 观测值 0
  - 2 分 → 25
  - 3 分 → 50
  - 4 分 → 75
  - 5 分 → 100
- 每次重练都算一次练习，`practice_count` 会累加。这是刻意的：用户确实又练了一次。
- 画像重建必须把重练记录纳入重放，否则重建会丢掉重练带来的掌握度变化。

### 5.7 冷启动与空状态

- 没有错题：错题本展示空状态，引导“去面试”。
- 有错题但没有重练：只展示待重练，参考要点区域提示“提交后可查看”。
- 画像为空但有错题：错题本仍然可用；重练后画像自动出现该知识点。

## 6. 页面与交互

### 6.1 错题本页 `/wrong-questions`（新增侧边栏入口）

**顶部统计**：待重练 / 今日待复习 / 已掌握 / 累计错题。

**Tab**：待重练 / 已掌握 / 全部。

**筛选**：
- 按知识点筛选：从掌握度画像页、复盘报告跳转时自动带入。
- 按本场面试筛选：从复盘报告跳转时自动带入。
- 有筛选时展示一个可关闭的筛选标签，例如“知识点：HashMap ×”。

**列表字段**：

| 字段 | 说明 |
|---|---|
| 题目摘要 | 题干前 120 字，换行折叠 |
| 知识点 | 1~3 个标签 |
| 原评分 | 1~5 分 |
| 状态 | 待重练 / 已掌握 |
| 重练次数 | 累计提交次数 |
| 最高分 | 历史重练最高分 |
| 最近重练 | 相对时间，如“2 天前” |
| 下次复习 | 日期或“今天该练了” |

**排序**：待重练优先；同状态按 `next_review_at` 升序，再按收录时间倒序。

**操作**：卡片右侧按钮“重练”或“再练一次”。

**空状态**：

```
还没有错题
在 AI 面试里答得不够好的题，会自动收进这里。
[去面试]
```

**移动端**：统计卡两列，列表卡纵向排列，不出现横向滚动。

### 6.2 重练弹窗

打开时：

```
[题目] 说说 HashMap 的 put 流程？
[追问] 如果发生哈希冲突，链表和红黑树怎么切换？
[知识点] HashMap
[原评分] 2 / 5

提示：提交后可查看原回答与参考要点，先自己写一遍。
[作答框]
[提交重练]
```

提交后：

```
本次得分 4 / 5    已掌握
点评：……
建议：……
参考要点：
- ……
- ……
原回答（可展开）
重练历史（最近 3 次）
[再练一次]
```

规则：
- 作答框最多 4000 字，至少 10 字。
- 支持 `Ctrl / Cmd + Enter` 提交。
- 提交中禁用按钮，防止连点。
- 失败时保留已输入内容，提示“AI 批改失败，请稍后重试”。
- 已掌握的错题仍可“再练一次”。

### 6.3 答题后即时提示

本题收束且得分 ≤ 2 时，在面试对话页显示一条非阻塞提示：

```
本题已加入错题本 · 立即重练 →
```

- 点击跳 `/wrong-questions?open={wrongId}`，自动打开该题的重练弹窗。
- 收录失败时不显示提示，不影响答题主流程。

### 6.4 复盘报告联动

报告底部增加：

```
本场有 3 道错题已加入错题本。去重练 →
```

- 数量来自本次会话收录的错题数；为 0 时不显示。
- 点击跳 `/wrong-questions?sessionId={sessionId}`。

### 6.5 掌握度画像联动

画像页每个知识点行增加一个轻量入口：

```
[错题 →]
```

- 点击跳 `/wrong-questions?kpId={knowledgePointId}`。
- 该知识点没有错题时，错题本展示“这个知识点下还没有错题”的筛选空状态，不报错。

### 6.6 面试入口联动

面试配置页的“你的薄弱知识点”卡片底部增加：

```
去错题本重练 →
```

不改变创建面试的流程，也不增加配置项。

### 6.7 文案口径

- 统一使用“错题本”“重练”“参考要点”“待重练”“已掌握”“今日待复习”。
- 避免“你答错了”“你很差”这类负面表达，改成“这道题还可以再练一次”。
- 参考要点统一标注“AI 生成，仅供复习参考”，不说“标准答案”。

## 7. 边界与异常

| 场景 | 行为 |
|---|---|
| 同一道题重复收束 | 唯一键兜底，只收录一次 |
| 题目未收束 / 没有评分 | 不收录 |
| 删除面试记录 | 错题快照保留，仍可重练 |
| 删除简历 | 不影响错题快照 |
| 知识点为空 | 仍然收录，但不能按知识点筛选；重练不回写画像 |
| 重练 LLM 失败 | 返回 502，不写重练记录，不改状态，用户可重试 |
| 重复点击重练 | 服务端按错题加锁，前端禁用按钮，只处理一次 |
| 已掌握后重练失败 | 状态回退为待重练，`mastered_at` 清空 |
| 原回答过长 | 快照截断到 6000 字，详情页提示已截断 |
| 重练答案过短 | 少于 10 字拒绝提交 |
| 参考要点为空 | 视为模型输出异常，返回 502 |
| 历史数据 | 管理员按用户回填，只补缺，不删除已有重练记录 |
| 用户想删除错题 | 本期不支持，后续再加 |

## 8. 验收标准

| # | Given | When | Then |
|---|---|---|---|
| 1 | 用户完成一道题且得分 2 | 查看错题本 | 出现 1 条待重练，题目、原评分、知识点正确 |
| 2 | 用户完成一道题且得分 3 | 查看错题本 | 不出现该题 |
| 3 | 同一道题被重复收束 | 再次触发收录 | 错题本仍只有 1 条，不重复 |
| 4 | 用户重练得 2 分 | 提交后 | 状态仍为待重练，重练次数 +1，下次复习为 1 天后 |
| 5 | 用户重练得 4 分 | 提交后 | 状态变为已掌握，最高分 4，下次复习为 7 天后 |
| 6 | 已掌握错题再练得 1 分 | 提交后 | 状态回退待重练，`mastered_at` 清空 |
| 7 | 首次打开错题详情 | 未提交重练 | 不返回原回答和参考要点 |
| 8 | 提交一次重练后 | 再次打开详情 | 返回原回答、本次参考要点和重练历史 |
| 9 | 重练时模型输出非法 | 提交 | 返回 502，不产生重练记录，状态不变 |
| 10 | 两个请求同时重练同一题 | 并发提交 | 只有一个成功，另一个返回 409 或等待后串行处理 |
| 11 | 用户有历史低分题 | 管理员触发回填 | 缺失的错题被补齐，重复执行不产生重复数据 |
| 12 | 用户从画像点“错题 →” | 进入错题本 | 列表只展示该知识点的错题 |
| 13 | 用户从复盘报告进入 | 查看报告底部 | 显示本场错题数，点击进入本场错题列表 |
| 14 | 答题得分 2 | 本题收束 | 面试页出现“已加入错题本”提示，可直达重练 |

## 9. 里程碑

| 阶段 | 内容 | 产出 |
|---|---|---|
| M1 | 错题表 + 自动收录 + 管理员历史回填 | 错题能被稳定收进来 |
| M2 | 重练接口 + LLM 评分 + 参考要点 + 画像回写 | 错题能被练、能改变画像 |
| M3 | 错题本页 + 重练弹窗 | 用户可见、可操作 |
| M4 | 答题后提示 + 复盘/画像/面试入口 + 验收 | 闭环可演示、可上线 |

M1/M2 是闭环内核，必须先于 M3；否则错题本没有真实数据，也无法证明“练了有用”。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 2 分才收录，阈值过严导致错题本空 | 先按 2 分上线，观察收录量；P1 增加“手动加入错题本” |
| 模型给的参考要点有错 | 明确标注“AI 生成，仅供参考”；不叫标准答案；后续接题库/人工校对 |
| 用户反复刷同一题抬高画像 | 每次重练是真实练习，允许计数；后续可加“同一题每天最多计一次”冷却 |
| 用户直接看参考要点再作答 | 提交前不返回参考要点，原回答也先隐藏 |
| 重练回写画像后，重建丢数据 | 画像重建同时重放面试题和重练记录 |
| 收录失败导致错题缺失 | 收录是旁路，不阻塞答题；管理员回填兜底 |
| 重练 LLM 延迟高 | 非流式调用，前端明确 loading；失败可重试；不阻塞其他题 |
| 错题越积越多，用户不想看 | 默认展示“待重练”，已掌握折叠到 tab；后续加批量清理 |
| 指标好看但用户不练 | 以北星指标为准，重点看“7 天内重练率”而不是收录数量 |

## 11. 已拍板与待确认

已拍板：

1. 本题收束且得分 ≤ 2 自动收录，一题一条。
2. 重练得分 ≥ 3 标记已掌握，< 3 待重练；已掌握可回退。
3. 参考要点只在重练提交后展示，原回答同步解锁。
4. 重练使用快照知识点回写画像，画像重建纳入重练记录。
5. 本期不做手动录入、相似题、SM-2、推送、错题删除。

待确认（建议默认值）：

1. 重练答案最短 10 字（默认）。
2. 复习间隔 1 / 3 / 7 天（默认）。
3. 答题后是否立即提示“已加入错题本”（默认提示，可直达重练）。
4. 是否允许用户删除错题（默认不提供，后续再加）。
